# NewAPI 签到 · 远程配置管理平台

## 项目概述

在 GitHub Actions 定时跑签到，每次运行前从**自建的配置管理网站**拉取最新配置，实现：

- 网页化管理所有配置（账号增删改、AI、浏览器、代理池、通知邮箱……）
- 每次 Actions 签到前自动同步远程配置，改网页 = 改配置，**永不改动 GitHub Secret**
- Secret 里只保留：远程配置地址 + API Key + 一份精简兜底配置

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Go 1.22+（标准库 net/http + JWT） | 单二进制零依赖，VPS 好部署 |
| 数据库 | modernc.org/sqlite（纯 Go 无 CGO） | 单文件，无需安装 sqlite |
| 前端 | Vue 3 + Vite + Naive UI + Pinia | 中文生态好、组件全 |
| 鉴权 | 管理员账号密码 → JWT 管理后台；API Key 供 Actions 拉取 | 权限分离 |
| 部署 | systemd + Nginx 反代 + HTTPS | Ubuntu 24.04 |

## 部署环境

- VPS：Ubuntu 24.04
- 域名：已有并解析到 VPS
- 目录结构（VPS 上建议）：

```
/opt/newapi-config/            # 部署根目录
├── newapi-config-server       # Go 后端单二进制
├── web/                       # Vue 构建产物（静态文件）
├── data/                      # SQLite 数据库文件（自动创建）
└── .env                       # 环境变量（JWT 密钥等）
```

# 一、远程可拉取的配置信息全量清单

> 以下所有字段都可通过远程配置网站管理，Actions 签到前拉取后覆盖本地。
> 完整结构即 `config.example.json` 的字段集；本清单按「功能模块」分组，标注：
> - **必填**：缺失会导致该模块不可用
> - **可选**：有默认值，可不填
> - ⚠️ 敏感：cookie / 密钥类，页面显示时默认打码

## 1. 账号管理（accounts）

**签到核心**，可任意增删改。每个账号独立一行。

| 字段 | 类型 | 必填/可选 | 默认 | 说明 |
|---|---|---|---|---|
| `name` | string | 必填 | — | 账号显示名（建议用不敏感的代号，会出现在公开日志/邮件里） |
| `url` | string | 必填 | — | 站点地址，如 `https://gorouter.app`（必须以 http(s):// 开头） |
| `login_method` | enum | 可选 | `newapi_cookie` | `newapi_cookie` 使用站点 Cookie；`github_cookie` 使用 GitHub OAuth Cookie |
| `cookie` | string | 条件可选 | 空字符串 | ⚠️ 站点登录 Cookie；`login_method=newapi_cookie` 时使用 |
| `github_user_session` | string | 条件可选 | 空字符串 | ⚠️ GitHub `user_session` 值；`login_method=github_cookie` 时使用 |
| `github_client_id` | string | 可选 | 空字符串 | GitHub OAuth Client ID；留空时从站点 `/api/status` 的 `github_client_id` 读取 |
| `user_id` | int | 可选 | 自动探测 | New API 用户 ID；留空则首次运行时自动获取并缓存 |
| `proxy` | string | 可选 | 直连 | 手动指定代理（`http://user:pass@host:port`）；填了则不用代理池 |
| `checkin_path` | string | 可选 | 自动探测 | 签到接口路径，如 `/api/user/checkin`（留空自动探测） |
| `browser_path` | string | 可选 | `/dashboard` | 浏览器入口页面路径 |
| `enabled` | bool | 可选 | `true` | 是否启用（停用 = 不参与本轮签到） |

> 前端表格操作：新增/编辑/删除/启停/分别编辑两类 Cookie/批量操作。两类 Cookie 均独立打码，切换登录方式不会清空另一套字段。
>
> 可用性检查由 Python 运行时分别执行：
> `python main.py --cookie-test newapi_cookie` 只检查站点 Cookie，
> `python main.py --cookie-test github_cookie` 只检查 GitHub Cookie；两者都不会执行真正签到回调。

## 6. 代理池（proxy_pool）⭐ 防单 IP 风控核心

免费代理池，每账号独立 IP。

> 管理端「Cookie 可用性测试」页也共用这份代理池（`proxies` 表的 alive 记录），且**不受 `enabled` 开关限制**：
> 账号填了 `proxy` 就优先用它（连续 2 轮失败后降级到池子），否则从池子轮转取出口；池子为空则该轮直连。
> 检测遇到代理/CDN 拦截会换出口无限重试，只有站点或凭据本身给出结论才停止，可在页面上手动停止。

| 字段 | 类型 | 必填/可选 | 默认 | 说明 |
|---|---|---|---|---|
| `enabled` | bool | 可选 | `false` | 是否启用代理池 |
| `test_url` | string | 可选 | `https://api.ipify.org` | 连通性测试接口（**只打探活站，不打目标站**） |
| `timeout` | int | 可选 | `8` | 单代理测通超时（秒） |
| `max_workers` | int | 可选 | `25` | 测通并发数 |
| `max_proxies` | int | 兼容字段 | `250` | 当前本地测通流程不再按此字段截断候选 |
| `ip_swap_limit` | int | 兼容字段 | `10` | 网络异常换 IP 不受此字段限制；其他失败按运行器策略处理 |
| `sources` | string[] | 可选 | 内置默认源 | 自定义代理源列表（空=内置 6 个源：monosans/TheSpeedX/proxy4parsing/clarketm/jetkai/89ip） |
| `remote_url` | string | 可选 | 空 | 配置管理平台代理预取接口；成功时签到端直接使用服务端测通列表 |
| `save_limit` | int | 可选 | `0` | 服务端可用代理保存数量；`0` 表示不限量 |
| `refresh_minutes` | int | 可选 | `30` | 服务端后台刷新间隔；小于等于 0 关闭自动刷新 |

## 鉴权

| 方式 | 适用 | Header |
|---|---|---|
| **JWT** | 后台管理（登录后获取） | `Authorization: Bearer <jwt>` |
| **API Key** | Actions 拉取配置 | `Authorization: Bearer <api_key>` |

## 接口列表

### 管理端（JWT）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/login` | 管理员登录，返回 JWT |

| 方法 | 路径 | 说明 |
|---|---|---|

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 存活探测 |

# 三、GitHub Actions 集成

## 1. Secret 设置（只需一次）

仓库 → Settings → Secrets and variables → Actions，设置：

| Secret | 值 |
|---|---|
| `CONFIG_JSON_B64`（推荐） | 含 `config_sync` 段的完整配置的 base64 文本；避免 GitHub 对结构化 Secret 脱敏时误伤日志中的账号名、IP、user_id 和普通数字 |
| `CONFIG_JSON`（兼容） | 含 `config_sync` 段的完整配置（远程拉不到时的兜底）；直接保存 JSON 可能导致 Actions 日志中的匹配片段显示为 `***` |

生成 `CONFIG_JSON_B64`：

- Windows PowerShell：`[Convert]::ToBase64String([IO.File]::ReadAllBytes('config.json'))`
- Linux/macOS：`base64 -w 0 config.json`

其中 `config_sync` 段示例：

```json
{
  "config_sync": {
    "enabled": true,
    "url": "https://config.yourdomain.com/api/config/raw",
    "method": "GET",
    "token": "在配置网站创建的 API Key",
    "token_header": "Authorization",
    "token_prefix": "Bearer",
    "timeout": 20,
    "auto_before_checkin": true
  },
  "accounts": [ { "name": "兜底账号", "url": "https://xxx.com", "cookie": "..." } ]
}
```

## 2. 签到流程（改造后）

```
Actions 启动
  → 读取 secret 落盘的 config.json（含 config_sync 段）
  → main.py 签到前调用 sync_remote_config()
      ├─ 成功：远程配置覆盖本地 → 用最新配置签到
      └─ 失败：WARN + 用本地兜底配置签到（不中断）
  → 按 accounts[].login_method 选择登录链路
      ├─ newapi_cookie：现有 /api/user/self + New-Api-User + 签到接口
      │                → Cloudflare/Turnstile 时复用浏览器与 AI 过盾
      └─ github_cookie：POST 站点 OAuth state（取 data.flow_token）
                       → GitHub authorize(user_session)
                       → 站点 OAuth callback 触发签到
                       → 站点质询时复用浏览器与 AI 过盾
  → 签到 + 邮件通知
```

> 远程配置**不可用时不阻塞签到**，保证系统健壮。

# 五、部署（Ubuntu 24.04 + systemd + Nginx）

## 1. 构建

```bash
# 后端（在项目 server/ 目录）
cd server && CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o newapi-config-server .

# 前端（在项目 web/ 目录）
cd web && npm install && npm run build   # 产物在 web/dist/
```

## 2. 放置文件

```bash
sudo mkdir -p /opt/newapi-config/{web,data}
sudo cp newapi-config-server /opt/newapi-config/
sudo cp -r web/dist/* /opt/newapi-config/web/
```

## 3. 环境变量（.env 或 systemd Environment）

| 变量 | 说明 |
|---|---|
| `NCF_DB_PATH` | SQLite 路径，默认 `./data/config.db` |
| `NCF_ENV` | 运行环境；`production` 时必须显式设置 JWT 密钥和初始管理员凭据 |
| `NCF_JWT_SECRET` | JWT 签名密钥（至少 32 字符，`openssl rand -hex 32` 生成；生产必填） |
| `NCF_ADMIN_USER` | 初始管理员用户名（仅 users 表为空时使用） |
| `NCF_ADMIN_PASS` | 初始管理员密码（生产必填，禁止使用默认密码） |
| `NCF_HTTP_ADDR` | 监听地址，默认 `127.0.0.1:8080`（Nginx 反代，不直接暴露） |

## 4. systemd 服务

```ini
# /etc/systemd/system/newapi-config.service
[Unit]
Description=NewAPI Config Server
After=network.target

[Service]
WorkingDirectory=/opt/newapi-config
ExecStart=/opt/newapi-config/newapi-config-server
Restart=always
RestartSec=3
EnvironmentFile=/opt/newapi-config/.env

[Install]
WantedBy=multi-user.target
```

## 5. Nginx 反代 + HTTPS（certbot）

```nginx
# /etc/nginx/sites-available/newapi-config
server {
    listen 80;
    server_name config.yourdomain.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
sudo certbot --nginx -d config.yourdomain.com   # 自动加 HTTPS
```

## 6. 首次初始化

```bash
sudo systemctl enable --now newapi-config
# 浏览器访问 https://config.yourdomain.com
# 用 NCF_ADMIN_USER / NCF_ADMIN_PASS 登录 → 创建 API Key → 填配置 → 导出兜底
```

# 六、安全说明

- 后端**只监听 127.0.0.1**，全部流量走 Nginx HTTPS
- 密码用 **bcrypt** 哈希存储；API Key 只存**哈希**（创建时明文仅展示一次）
- JWT 有过期时间；生产环境必须通过 `NCF_JWT_SECRET` 注入密钥
- `/api/config/raw` 仅 API Key 可访问；Key 可随时删除吊销
- 远程同步保留本地配置加密状态，不会因为同步而明文落盘
- 登录接口按来源地址与用户名进行失败退避限流
- 建议：远程配置里同样不要放敏感账号名，cookie 用专属授权态；定期轮换 API Key
