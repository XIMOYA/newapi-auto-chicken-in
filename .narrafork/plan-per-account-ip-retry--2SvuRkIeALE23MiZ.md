# 账号级源站/WAF 换 IP 重试

## 目标

对 `FAILED`（源站业务失败）和 `WAF_BLOCKED`（WAF 硬封禁）两类结果：

- 每个账号最多额外更换 5 次 IP；
- 每次成功换 IP 后等待 5 秒，再重试该账号；
- 等待发生在该账号自己的 worker 线程中，不持有全局状态锁，不阻塞其他账号；
- 网络异常、盾类失败和认证/未知结果保持现有策略不变。

换 5 次后，实际最多执行 6 次尝试：初始 IP 1 次 + 5 个新 IP。

## 实施步骤

1. 修改 `newapi_checkin/runner.py`
   - 将 `SOURCE_IP_SWAP_LIMIT` 从 3 改为 5。
   - 新增源站/WAF 专用常量 `SOURCE_IP_SWAP_BACKOFF_SECONDS = 5`。
   - 更新相关 docstring 和注释中的“三次”描述。
   - 在 `_run_account_with_retries()` 的源站/WAF 分支中，只有 `_swap_pooled_proxy()` 成功后才调用 `time.sleep(5)`，随后继续当前账号的重试。
   - 不修改网络异常分支的立即换 IP，也不修改盾类分支已有退避；无新 IP 或手动代理仍立即跳过。

2. 更新 `tests/test_speed_guards.py`
   - 将源站失败和 WAF 硬封禁的旧“三次换 IP”断言改为“五次换 IP”，期望代理序列从 `p1` 到 `p6`。
   - 对会触发等待的测试打补丁避免真实等待。
   - 新增等待行为测试：成功换 IP 后恰好等待 5 次，每次参数均为 5 秒。
   - 保留网络异常无退避的断言，确保本次等待只作用于源站/WAF。

3. 增加并发隔离回归测试
   - 使用两个账号并发执行：一个账号进入源站/WAF 重试并等待，另一个账号立即成功。
   - 验证第二个账号无需等待第一个账号的 5 秒退避，证明等待只占用当前账号 worker。

4. 验证
   - 运行相关 pytest，随后运行全量 pytest。
   - 运行 `go vet ./...` 和 `go test ./...`。
   - 验证通过后按仓库既有格式自动创建新 git commit，不 push。
